# Intel Wi-Fi & Bluetooth Driver Manager 2.2.0 (предварительная версия)

## Режимы

Обычный запуск обновляет Wi-Fi и Bluetooth через проверенную базовую утилиту. `-Inventory` показывает установленные устройства Intel без установки. `-Graphics` отдельно проверяет некоторые Core i3/i5/i7/i9 7–10 поколений с Intel HD/UHD/Iris Plus на Windows 10 (от 1809) или 11 x64, предлагает загрузку пакета Intel 31.0.101.2145 и запуск интерактивного установщика. Менеджер сверяет Intel PCI Vendor ID, семейство графики, процессор и ОС; полный список PCI Device ID из подписанного INF пока не включён, поэтому окончательную совместимость проверяет Intel. `-GraphicsInstallerPath` позволяет выбрать уже загруженный установщик. Этот пакет не является обновлением процессора или чипсета.

При интерактивном запуске предлагается выбрать язык сообщений менеджера; `-Language ru` и `-Language en` позволяют задать его без вопроса. Через UAC выбор передаётся в новый процесс. Внешние установщики и базовая утилита не переводятся. Для `-Silent` язык по умолчанию русский.

Для режима Graphics менеджер сверяет SHA-512 с опубликованным Intel значением и подпись установщика, а после закрытия повторно читает версию драйвера. Код `1000` наблюдался при успешной установке на испытанном компьютере, но сам по себе успех не подтверждает. После подтверждённой установки либо документированного кода установщика менеджер отдельно предлагает перезагрузку. Режим `-Silent` к графике не применяется.

Консольная сессия записывается в файл `%LOCALAPPDATA%\IntelWiFiBTManager\Logs`; путь к журналу выводится при запуске. Журнал может содержать имена устройств, пути и сообщения установщика, поэтому просмотрите его перед публикацией.

## Отчёт об обновлениях

`-CheckUpdates` не требует прав администратора и только сравнивает версии Wi-Fi, Bluetooth и поддерживаемой Intel Graphics. Беспроводные устройства сопоставляются с таблицами FirstEverTech по точным PCI/USB ID, графика — с закреплённым пакетом Intel. Неизвестный ID, нераспознанная версия или недоступный источник означают «не удалось определить», а не «обновлений нет». Таблицы стороннего проекта служат для предварительного уведомления; до установки отдельный модуль должен повторно проверить источник, пакет и совместимость. Графика Core 6-го поколения определяется отдельно только для справочного сравнения с архивной версией Intel 31.0.101.2115; это не подтверждённое обновление для Windows 11 и не путь установки. Если Intel Wi-Fi/Bluetooth отсутствуют, их таблицы не запрашиваются. Команда не проверяет чипсет, BIOS и микрокод.

## Алгоритм

1. Проверяет права администратора. В интерактивном режиме предлагает перезапуск через UAC; в автоматическом режиме требует заранее повышенных прав.
2. Показывает адаптеры Intel и текущие версии через Win32_PnPSignedDriver. Если подходящих устройств нет, завершает работу с ошибкой.
3. Проверяет NuGet и получает метаданные пакета из PSGallery. Сравнивает имя пакета, автора Marcin Grygiel и адрес проекта FirstEverTech/Universal-Intel-WiFi-BT-Updater.
4. Скачивает конкретную версию базовой утилиты через Save-Script в отдельную временную папку запуска, проверяет метаданные файла и запускает проверенную копию. После завершения папка удаляется.
5. Запускает базовую утилиту в Windows PowerShell. В обычном режиме она управляет показом версий и подтверждениями. При `-Silent` передаётся `-auto`.
6. Дожидается завершения процесса. Ненулевой код дочернего процесса отображает как ошибку; менеджер возвращает 1. Нулевой код возвращает как 0 и в интерактивном режиме ожидает Enter.

## Проверенный список кандидатных пакетов

`data/driver-packages.json` хранит пока одну запись: закреплённый пакет Intel Graphics 31.0.101.2145. В ней указаны страница источника, адрес установщика, SHA-512, ожидаемый издатель и дата ручной проверки. Команда `tools/Test-DriverCatalogue.ps1` проверяет структуру записи, адреса, хеш и дату без сетевых запросов. Тест сверяет версию, URL и хеш с текущими константами менеджера.

Режим `-CheckUpdates` показывает источник графического кандидата и дату ручной проверки, когда файл каталога находится рядом с менеджером в `data`. При запуске одного скачанного `.ps1` без папки `data` используется встроенный закреплённый пакет; отсутствие каталога сообщается явно. Каталог не сообщает о новых релизах и не управляет установкой. Статус `VALID_STRUCTURE` подтверждает формат данных, а не актуальность доступного пакета или совместимость конкретного ПК. Новые Wi-Fi/Bluetooth пакеты добавляются только после отдельной проверки источника и хеша.

Отчёт `Test-DriverPackage.ps1` дополнительно показывает `SystemInfCatalogSignature`: Windows может подтверждать подпись INF через системный каталог. Это самостоятельное наблюдение и не заменяет `InfCatalogMembership`, которое требует проверки экспортированного INF против конкретного экспортированного CAT.

## Совместный отчёт по устройству и пакету

`tools/Test-DriverCandidate.ps1` объединяет два локальных отчёта INF с аудитом конкретного пакета. Он принимает установленный и кандидатный JSON-отчёты, путь проверяемого INF и аппаратный ID устройства. Для оценки секции Windows передайте архитектуру и номер сборки. Например:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-DriverCandidate.ps1 -InstalledReport 'C:\Drivers\installed.json' -CandidateReport 'C:\Drivers\candidate.json' -CandidateInf 'C:\Drivers\Candidate\netwtw08.inf' -HardwareId 'PCI\VEN_8086&DEV_02F0&SUBSYS_00748086\1' -Architecture amd64 -OsBuild 26200 -Language ru
```

Добавьте `-VerifyInstalledDevice`, чтобы сравнить аппаратный ID и версию в отчёте с реально установленным устройством через Windows. Без этой проверки вывод `CANDIDATE_FOR_REVIEW` недоступен. Если версия в Windows изменилась со времени создания отчёта, результатом будет `REJECT`; если устройство не найдено, потребуется ручная проверка. Команда только читает сведения об устройствах и не требует прав администратора.

Для ZIP добавьте `-PackageFile`, хеш из доверенной записи (`-ExpectedSha256` или `-ExpectedSha512`), `-ArchiveEntry` и, при наличии SDK, `-SignToolPath`. Кандидатный JSON должен ссылаться на тот же локальный INF, который передан через `-CandidateInf`. Инструмент повторно разбирает INF во временной папке `%LOCALAPPDATA%\IntelWiFiBTManager\Work` и сравнивает все строки моделей с переданным JSON. Расхождение приводит к `REJECT`; временный отчёт удаляется. Вывод `REJECT` означает конкретное несоответствие; `NO_NEWER_VERSION` — версия не новее; `MANUAL_REVIEW` — сведений недостаточно. Даже `CANDIDATE_FOR_REVIEW` означает лишь завершение локальных предварительных проверок и не разрешает установку. Полная комплектность пакета, актуальность онлайн-источника, ранжирование Windows и ограничения производителя пока не проверяются. Инструмент ничего не скачивает и не устанавливает.

## Локальные кандидаты при проверке устройств

Если у вас уже есть извлечённый пакет и оба отчёта INF, добавьте JSON со списком кандидатов и запустите `-CheckUpdates -CandidateManifest 'C:\Drivers\candidates.json'`. Менеджер проверит кандидата только тогда, когда точный `deviceId` совпадает с обнаруженным Intel Wi-Fi, Bluetooth или Graphics. Отсутствующие устройства он пропустит; совпадающие передаст в `tools/Test-DriverCandidate.ps1` с обязательной сверкой установленной версии через Windows.

Пример структуры файла (Windows-пути в JSON требуют двойной обратной косой черты):

```json
{
  "entries": [
    {
      "deviceId": "PCI\\VEN_8086&DEV_02F0&SUBSYS_00748086\\3&11583659&0&A3",
      "installedReport": "C:\\Drivers\\installed.json",
      "candidateReport": "C:\\Drivers\\candidate.json",
      "candidateInf": "C:\\Drivers\\Candidate\\netwtw08.inf",
      "packageFile": "C:\\Drivers\\candidate.zip",
      "expectedSha256": "ЗАМЕНИТЬ_ПРОВЕРЕННЫМ_SHA256",
      "archiveEntry": "drivers/netwtw08.inf",
      "sourceUrl": "https://example.invalid/official-package.zip"
    }
  ]
}
```

Пример содержит условные пути и URL: его нельзя использовать как готовый пакет или источник хеша. Для EXE поле `archiveEntry` не применимо, связь INF с содержимым EXE остаётся непроверенной. Путь к проверочному модулю должен находиться в `tools` рядом с менеджером; один отдельно скачанный `.ps1` этой функцией не пользуется. Список локальный: программа пока не ищет, не загружает и не устанавливает новые пакеты по этим записям. Файл следует создавать только для пакетов, проверяемых для вашего устройства.

## Пробная проверка на установленном драйвере

`tests/LiveInstalledCandidate.ps1` выбирает одно обнаруженное устройство Intel (сначала сетевое, иначе графику), читает его установленный INF из Windows, создаёт локальную копию в ZIP и запускает `-CheckUpdates -CandidateManifest`. Ожидаемый результат — `NO_NEWER_VERSION`, проверка устройства `PASS` и совпадение INF с ZIP `PASS`. Утилита удаляет только созданную ею временную папку из `Work`; журнал менеджера сохраняется. Этот тест не скачивает драйвер и не устанавливает его.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\tests\LiveInstalledCandidate.ps1' -Language ru
```

ZIP и его SHA-256 получаются из уже установленного INF прямо во время теста. Они **не подтверждают происхождение от Intel и не являются кандидатом на обновление**. Проверка реального нового выпуска потребует отдельно полученного пакета и хеша из доверенного источника.

## Временные файлы менеджера

Новые загрузки менеджера помещаются в отдельную папку `%LOCALAPPDATA%\IntelWiFiBTManager\Work\<ID запуска>`. После завершения дочернего процесса и запроса перезагрузки менеджер удаляет только папку своего запуска. Журналы находятся отдельно в `Logs` и сохраняются. Файл, заданный параметром `-GraphicsInstallerPath`, не удаляется. Старые папки `Updater` и `Graphics`, созданные предыдущими версиями, также не удаляются автоматически.

Сторонняя утилита и установщик Intel могут создавать собственные файлы вне `Work`; менеджер не управляет их очисткой. При невозможности удалить свою папку он выводит предупреждение и сохраняет журнал для диагностики.

## Локальная проверка пакета (предварительно)

`tools/Test-DriverPackage.ps1` читает уже имеющийся INF и, по желанию, исходный архив или установщик. Он не загружает и не устанавливает драйвер. Пример для экспортированного пакета:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-DriverPackage.ps1 -InfPath 'C:\Drivers\Export\netwtw08.inf'
```

Если имеется исходный загруженный файл и заранее известный SHA-256 или SHA-512, передайте `-PackageFile` и `-ExpectedSha256` либо `-ExpectedSha512`. Параметр `-SourceUrl` лишь записывает заявленный адрес; он не доказывает происхождение файла. Для проверки связи INF с подписанным каталогом нужен `signtool.exe` из Windows SDK: укажите `-SignToolPath` либо добавьте его в PATH. При отсутствии SignTool результат `InfCatalogMembership` останется `UNVERIFIED`. Для ZIP-архива можно дополнительно указать `-ArchiveEntry 'drivers/netwtw08.inf'`: аудит сравнит SHA-256 именно этой записи внутри архива с извлечённым INF. Имя записи должно точно совпасть, включая регистр. Отсутствие записи, несколько одинаковых записей или расхождение байтов дадут `ArchiveInfLink = FAIL`. Без `-ArchiveEntry`, а также для EXE и других контейнеров связь остаётся `UNVERIFIED`; их нельзя выдавать за проверенный ZIP. `LOCAL_CHECKS_PASSED` теперь требует одновременно совпадения заранее известного хеша архива, подписи каталога, проверки INF против данного CAT через SignTool и связи ZIP с INF. Хеш следует брать из доверенной записи о выпуске: самостоятельно рассчитанный хеш подтверждает лишь постоянство локального файла. Даже все эти проверки не подтверждают совместимость с устройством, полную комплектность пакета или происхождение по одному заявленному URL и не разрешают установку.

## Ограничения

Метаданные автора и проекта не являются цифровой подписью и не гарантируют целостность кода. Проверки драйверов, создание точки восстановления и установка реализованы базовой утилитой. Успешное завершение процесса не заменяет проверку фактической версии драйвера после установки.

Менеджер не использует Get-InstalledScript, Install-Script или Update-Script. Сведения InstalledLocation не влияют на выбор файла. Путь к самому менеджеру может быть произвольным.

`-Silent` означает автоматическое подтверждение действий, а не скрытое окно или отсутствие консольного вывода. Поведение автоматического режима определяется базовой утилитой; этот режим ещё не проверен на пользовательском ПК.

Для работы нужны Windows, Windows PowerShell 5.1, PowerShellGet и доступ к PSGallery, GitHub и источникам драйверов базовой утилиты. Ошибки сетевых запросов обрабатываются без проверки доступности через ICMP/ping.

## Проверенные сценарии

См. [историю изменений](CHANGELOG.md). Проверена работа с базовой утилитой 2026.7.8, продолжение журнала после UAC и сценарии `-Inventory`/`-Graphics` с уже актуальным драйвером. На одной системе проверено обновление Intel UHD Graphics до 31.0.101.2145 и сохранение версии после перезагрузки. Тест `tests/RestartPrompt.Tests.ps1` проверяет решение о перезагрузке и ответы `Y/N` с подменой `Restart-Computer`. На чистой Windows и другом оборудовании проверка ещё не проводилась; предложение перезагрузки после реальной новой установки отдельно не проверено.
